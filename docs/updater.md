# Shared installation and signed Update

One per-user Windows installation supplies private CPython 3.14.10, the command, native desktop and packaged blueprint. Projects remain outside the installation. Source commands use a development environment and do not replace the installed app. `install.ps1` stages a candidate, verifies pinned artifacts and private imports, checks native installation health, serializes setup and safely replaces/reverts the inventory-owned installation. Uninstall retains external project/user state and refuses nested project markers.

The Update button and `corinthos update check|start|status|finish` retain explicit stable-release checking, staging, same-operation status, BUSY handling and recovery. The updater authenticates exact manifest bytes using the pinned Ed25519 public key before trusting bounded artifact metadata. Archive paths, links, lengths, hashes, complete payload inventory and embedded installation/release identity are verified before replacement. A disposable signing key is appropriate for tests; production private keys stay outside source and are never needed by application checks.

The replacement manifest uses `schema: 2` and `workspace_format: 1`; release metadata uses `workspace_format: 1`. This is passive compatibility metadata, not a project contract. Incompatible formats are rejected. Old schema9 contract-based installations cannot consume the new manifest through their old verifier; no automatic legacy migration or unsigned bypass is supplied. This source snapshot does not publish a release.

Every installed client and detached worker holds the shared runtime lease. Update finish checks live worker ownership across projects; replacement must additionally acquire the exclusive runtime handle. Close clients and cancel/wait for workers before finishing. Ambiguous ownership remains busy. Staging, helper handoff, native health, rollback and project preservation remain in the installation scripts. `code-updater` is a project cleanup skill and is unrelated to this installed-app updater.

The desktop shell displays Update while Engine views remain unavailable. Real release publication, production-key use and real-user installation replacement are separate owner actions. Controlled tests and disposable CI installations verify current safety paths; they do not claim live AI-provider or GUI visual acceptance.
