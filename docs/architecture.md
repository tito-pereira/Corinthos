# Implemented architecture

The Python package composes workspace, skills, runtime, continuity and installed-app Update. `application/service.py` is the shared operation boundary; `cli.py` and `application/sidecar.py` adapt it to the terminal and bounded JSON-RPC. The native Tauri shell retains protocol negotiation, process supervision, assets, health and Update handoff. Engine views are gated off for the replacement backend.

`workspace.py` initializes missing blueprint content and validates explicit root-bound UUID metadata. `resources/blueprint` contains the full selected 17-skill library with source/distributed hashes and normalization provenance. Installed resources are read through `importlib.resources`. Incompatible old project markers are refused without opening or modifying their databases.

`skills.py` loads the current project's customized skill and bounded instructions/context/task inputs. No Python engine decides planning stages, approvals or acceptance. Each requested skill is one provider process; independent review and corrections are separate invocations guided by their local skill files.

`runtime.py` admits runs under a project lock, rejects overlapping case-insensitive parent/child write scopes and creates isolated workspace copies or clean Git clones. A detached `worker.py` owns native descendants through retained Windows Jobs/POSIX process control. Per-run ownership records and locks live in shared user state outside movable project folders; idle moved/deleted projects cannot block Update. Live ownership and ambiguous records remain busy; expired unowned admissions are removed. Cancellation markers and bounded status/output persist across client restarts. Integration validates declared changes and unchanged destination fingerprints; canonical source merges remain explicit coordinator actions. Trusted local tools can escape filesystem isolation through their ordinary OS privileges; this is not a sandbox.

Project state is bounded current JSON in `context_agents/corinthos`: identity, run index and continuity. Workspace identity returns the validated stored root spelling, including through equivalent Windows path casing. Run workspaces/outputs remain inspectable until explicit summary-backed discard. `continuity.py` retains completed/pending/blockers/verification/resume and atomically consolidates under the project lock before report, group and planning cleanup. It preserves unresolved decisions by default. It does not maintain an append-only governance ledger.

Per-user recent-project/provider/update state is convenience and installation state, separate from project context. Explicit run roots remain unchanged by opening another project. Existing legacy provider choices remain stored but are not executed as new command vectors.

`filesystem.py` provides ordinary-path/link/hardlink checks, bounded atomic JSON and interprocess locks. `runtime_gate.py` retains shared installed-runtime admission. The signed updater uses passive workspace-format compatibility, exact-byte Ed25519 signatures, bounded archives/inventories, staging and native installation health, setup/runtime exclusion and recovery. See [Update](updater.md).
