# Implemented architecture

The Python package composes workspace, local skills, isolated execution, continuity and installed-app Update. `application/service.py` exposes shared operations; CLI and bounded JSON-RPC adapters call them. The Tauri shell owns transport, native folder selection, health and the separate Update finish handoff. React supplies exactly Main and Project pages, shared branded navigation and temporary overlays.

`workspace.py` fills missing blueprint content and validates root-bound UUID metadata. All 17 selected skills ship under package resources with provenance. Existing source, instructions and context remain intact; incompatible legacy markers are refused without database migration. GUI project name/description are retained in workspace metadata and normal PROJECT context.

`gui.py` composes explicit desktop requests through these existing boundaries. A detached `gui_worker.py` owns slow copying, preparation, provider waits, integration and publication; bounded per-user operation records expose actual status and errors. This is an operation lifecycle, not another Engine/governance framework. Each owner participates in runtime exclusion until its work is safe to release.

Creation bootstraps the local skill in newly owned sibling staging, invokes actual `create-project`, integrates its successful output and retains metadata. Publication requires no existing target, released provider ownership, a consolidated/discarded creation run and validated root rebinding. Only this operation's matching new UUID/stage can be finalized or recovered. Unmanaged imports use a disclosed independent source copy under `repo/`, including ordinary uncommitted/untracked files and custom context; originals and Git metadata remain untouched.

`gui_content.py` supplies bounded README/canonical/supporting context, local skill paths and deterministic fresh Markdown summaries. Runtime artifacts and inactive history are excluded from supporting context selection. Missing content and actual read errors are explicit. Task parsing uses structured group/status records, never status vocabulary appearing in explanatory prose. Opening informational views dispatches no provider.

`runtime.py` reserves claims quickly; snapshot preparation runs in the detached worker rather than the serialized request handler. Workers receive isolated copies or clean Git clones. Overlapping case-insensitive parent/child claims are rejected. Retained Windows Jobs/POSIX process control owns ordinary provider descendants. Per-run locks outside movable project folders distinguish live work from stale admissions, so moved/deleted idle projects do not permanently block Update.

Project conversations bind immutable UUID/root/conversation/run identities; Main uses a separate neutral application workspace. Project context is loaded before guidance/work. Per-user bounded transcripts and operation state are separate from project-local run inputs/outputs and continuity. Late responses and Apply/Discard/Cancel actions keep their original scope across project switches. Provider output is returned only through bounded owned-run reads, not arbitrary filesystem access.

Integration validates declared changed paths and original destination fingerprints before writes. A successful process has not automatically applied its work. I/O failures retain isolated output but integration is not a multi-file transaction; owner recovery can be necessary. Trusted local providers retain their ordinary OS privileges, so filesystem isolation is coordination rather than an OS sandbox.

`continuity.py` atomically retains completed/pending/blocker/verification/resume state before report, group, planning or run cleanup. Project identity, run index and continuity live in `context_agents/corinthos/`; unknown or incompatible state fails explicitly. Runtime/run/message/output retention is bounded. Recent projects are navigation hints, with only compact identity/name stored and at most ten displayed by the GUI.

The native method allowlist, backend advertisement and typed bridge are aligned. All application surfaces use the packaged reference identity; the owned Windows folder browser uses OS rendering. Update remains in a fixed sidebar footer and a shared overlay. Its origin, operation ID and WAITING_FOR_EXIT handoff are unchanged.

The shared Windows installation retains private Python, signed manifest schema 2/workspace format 1, exact-byte Ed25519 checks, bounded archive/path/hash/inventory validation, runtime/setup exclusion, staging, native health and recovery. No new release or legacy migration is implied. See [GUI](gui.md), [operations](backend.md) and [Update](updater.md).
