# Repository instructions

Use English for source, tests, documentation and user-visible text. Prefer correctness, simplicity and maintainability. Preserve MPL-2.0 and existing user work. Approved project decisions govern scope; routine technical choices do not need extra approval.

Corinthos now supplies prototype-based project workspaces and generic Python provider-process infrastructure. Project-local skills own the development process. Do not reintroduce legacy Engines, project-governance contracts, approval/publication gates or contract-derived context.

Keep explicit project binding, isolated worker outputs, coordinated write claims, compact continuity before every cleanup and one shared runtime for multiple projects. Preserve ordinary input/path validation, cancellation/reaping and signed Update/runtime exclusion/recovery. Never migrate or delete incompatible legacy project state implicitly.

Run the smallest checks relevant to the changed boundary; repeat only invalidated evidence. Report actual results and distinguish process completion from independent review, live-provider verification and product acceptance. The GUI has Main and Project pages with scoped conversations and explicit run actions; retain their context/identity binding, native ownership, assets, transport, health and Update.

Before publication inspect the complete diff for private data and machine-specific paths. Do not publish keys, local project context or runtime state. Use normal authorized branches/merges; preserve history and LICENSE. See [architecture](docs/architecture.md), [backend](docs/backend.md) and [Update](docs/updater.md).
